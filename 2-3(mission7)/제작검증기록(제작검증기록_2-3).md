* 수정 이유: 실수로 기록을 잃지 않게 미리 알려 주려고

* 수정 이유: 창을 단순하게, 단위 뜻을 필요할 때만 보이게

* 수정 후 테스트 결과: 휴대폰에서도 이미지가 만들어져 저장됨. PC 저장도 다시 확인함 (정상)
* 수정 이유: 휴대폰 사용자는 자기 결과 나무를 간직할 방법이 없음

### 수정 기록 49 (사용자 피드백 · PC·휴대폰)

* 발견한 문제: 같은 날 여러 날씨로 구워 여러 번 저장함. 예상: 파일마다 다른 이름. 실제: 날짜만 들어가서 같은 결과를 다시 저장하면 이름이 같아짐
* AI에게 전달한 요청: "같은 날에 저장 많이 하면 날짜가 또 같아서 … 그 시간까지 파일명에 넣어줘" (분까지)
* 수정 후 테스트 결과: '단풍나무굽기_활활단풍나무_나무_2026-11-12_2030.png'처럼 날짜 뒤에 시·분이 붙음
* 수정 이유: 여러 번 저장하면 어떤 파일이 언제 것인지 구분하기 어렵고 파일이 덮어쓰일 수 있음

### 수정 기록 50 (사용자 피드백 · 휴대폰·PC)

* 발견한 문제: 휴대폰에서 이미지 저장을 누름. 예상: 바로 기기에 내려받아짐. 실제: 글자가 깨진 이상한 내려받기 화면이나 공유 창이 뜸. PC에서도 저장 위치를 묻는 창이 뜸
* AI에게 전달한 요청: "핸드폰에서 저장할 때 이상한 저장 내려받기 화면이 엄청 깨져서 뜨는데 … 별도 팝업창 없이 버튼만 누르면 파일명은 pc랑 똑같은 형식으로 해서 다운로드 할 수 있게 해줘", "pc에서도 내려받을 곳 저장 위치 정하지 않고 바로 다운로드 되게"
* 수정 후 테스트 결과: PC·휴대폰 모두 '나무만'·'설명 포함'을 누르면 팝업이나 공유 창 없이 바로 파일로 내려받아지고 파일 이름 형식도 같음 (결과 화면이 나올 때 두 이미지를 미리 만들어 둠)
* 수정 이유: 깨진 화면이나 공유 창이 뜨면 저장이 된 건지 알 수 없고 사용자가 당황함

### 수정 기록 51 (사용자 피드백 · 휴대폰·PC)

* 발견한 문제: 휴대폰에서 '설명 포함' 이미지를 내려받아 봄. 예상: 휴대폰 화면에 맞는 그림. 실제: PC와 같은 16:9 가로 그림이라 휴대폰에서 보기 작고, 일부가 겹치거나 잘려 보임
* AI에게 전달한 요청: "핸드폰에서 내려받아 봤는데 이미지가 겹치거나 잘리는 부분 없이 일정여백을 모두 가진 9:16 비율로 저장되면 좋을 것 같고 pc에서는 16:9로 저장되면 좋을 것 같은데"
* 수정 후 테스트 결과: 휴대폰은 9:16(900×1600)으로 '제목 → 나무 → 설명 창'(설명 포함) 또는 '가운데 나무'(나무만) 순서로, PC는 16:9(1600×900)로 저장됨. 사방 여백이 있고 겹치거나 잘리는 부분 없음
* 수정 이유: 휴대폰 사진첩에서 가로 그림은 작게 보이고, 잘린 그림은 쓸 수 없음

### 수정 기록 52 (사용자 피드백 · PC·휴대폰)

* 발견한 문제: PC·휴대폰에서 화면을 봄. 예상: 모든 요소가 화면 테두리에서 적당히 떨어져 있음. 실제: 화면 크기에 따라 제목·나무·창·버튼이 가장자리에 너무 붙음
* AI에게 전달한 요청: "pc 랑 핸드폰 모두 위 아래 왼쪽 오른쪽에 도움말을 제외한 모든 요소를 글자 5자는 들어갈 정도로 여백을 두고 싶어"
* 수정 후 테스트 결과: PC·휴대폰 모두 도움말 버튼을 뺀 모든 요소가 창 가장자리에서 글자 5자 정도 떨어짐. 창 크기를 바꾸면 여백도 함께 커지고 작아짐. 도움말 버튼 자리는 그대로임을 확인함
* 수정 이유: 가장자리에 붙으면 답답하고, 휴대폰에서는 화면 둥근 모서리에 글자가 잘릴 수 있음

### 수정 기록 53 (사용자 피드백 · PC·휴대폰)

* 발견한 문제: '설명 포함' 이미지를 내려받아 화면과 비교함. 예상: 화면에서 보이는 배치와 여백 그대로. 실제: 저장 그림은 여백이 좁고 배치가 화면과 다름
* AI에게 전달한 요청: "지금 이미지 저장이 이런 식으로 된단 말이야 그런데 나는 이정도 여백으로 저장되게 하고 싶어 핸드폰에서는 이정도 여백으로 하고 싶어" (화면 캡처 3장 첨부)
* 수정 후 테스트 결과: PC·휴대폰 모두 '설명 포함' 이미지가 화면에서 보이는 배치와 여백 그대로(제목·나무·설명 창 둘레에 넉넉한 여백) 저장됨. 최종 HTML은 단풍나무_A_v3_Claude.html로 저장함
* 수정 이유: 화면에서 본 모습과 저장한 그림이 다르면 사용자가 원하는 결과를 간직할 수 없음

### 수정 기록 54 (기획서 정리)

* 발견한 문제: 최종 HTML(v3)과 기획서_v3를 비교함. 예상: 휴대폰·이스터에그 등 v3에서 바뀐 동작이 완료 기준과 기능 목록에도 들어 있음. 실제: 화면 구성에만 들어 있고, 완료 기준에는 v1 때 '휴대폰 폭 375px 배치' 한 줄뿐임. 필수·추가 기능 목록에도 휴대폰 지원과 이스터에그가 없음. 이미지 저장 부분에는 휴대폰 9:16과 맞지 않는 옛 16:9 문장 3곳(좁은 창도 16:9로 저장, '나무만'은 같은 16:9 크기, 설계 결정 36의 이미지 크기)이 남아 있음
* AI에게 전달한 요청: "완료 기준에 휴대폰 항목을 넣고, 추가 기능에 휴대폰 지원과 이스터에그를 넣는 게 좋아요. 앞에서 말씀드린 9:16 관련 옛 문장 3곳도 이때 같이 고치면 돼요." → "이렇게 넣고 제작검증기록에도 반영해줘"
* 수정 후 테스트 결과: 기획서_v3_상세 완료 기준 '공통'에 글자 5자 여백을 넣고, '휴대폰(터치 화면)'·'PC(마우스)'·'이미지 파일 이름'·'힐링·이스터에그' 항목을 새로 둠. 추가 기능에 이미지 저장(PC 16:9·휴대폰 9:16, 바로 내려받기, 파일 이름), 휴대폰 지원, 슬라이더 휠·힐링 중 제목 숨김·여백, 이스터에그를 넣음. 옛 16:9 문장 3곳은 'PC 16:9 / 휴대폰 9:16'으로 고침(PC는 창을 좁혀도 16:9, 휴대폰은 9:16 — v3 HTML 동작과 같음을 확인함). 기획서_v3_기본에도 완료 기준 휴대폰 한 줄과 추가 기능(이미지 저장·휴대폰 지원·이스터에그)을 더함. 제출용 기획서.md.md도 기획서_v3_상세와 같은 내용으로 맞춤. HTML은 고치지 않음
* 수정 이유: 기획서가 최종 HTML과 다르면 평가자가 기획서의 완료 기준만 보고 휴대폰 동작을 확인할 수 없고, 서로 맞지 않는 문장 때문에 어떤 동작이 맞는지 헷갈림

## 사용자 테스트

* 테스트 참여자와 요청한 작업: 제작자 본인이 PC와 휴대폰에서 v2 페이지를 처음 쓰는 사람처럼 사용함. 요청한 작업은 날씨 반죽 고르기 → 일수 고르기 → 굽기 → 더 굽기 → 결과 설명 읽기 → 힐링하기 → 이미지 저장까지 한 바퀴 해 보기
* 사용자의 행동과 질문:

  * 휴대폰: 말풍선 버튼을 누르자 안내 없이 바로 실행됨. "커서 올리면 안내문구가 뜨는 방식인데 핸드폰에서는 어떻게 알려 줘?" (수정 기록 37)
  * 휴대폰: 굽는 중 화면에서 '완료'·'더 굽기' 버튼이 창 아랫면과 겹친 것을 발견함. 제목이 화면 맨 위에 붙어 나무와 멀어 보임 (수정 기록 38, 39)
  * 휴대폰: 일수 선택기를 손가락으로 여러 번 밀어야 해서 불편해함. 슬라이더 손잡이를 정확히 누르지 못해 잘 안 움직임 (수정 기록 40, 43, 47)
  * 휴대폰: 이미지 저장이 안 되거나, 깨진 내려받기 화면·공유 창이 떠서 당황함. 저장된 그림이 가로 16:9라 휴대폰에서 작게 보임 (수정 기록 48, 50, 51)
  * PC: '나무만'과 '설명 포함'을 저장했더니 파일 이름이 같아서 직접 이름을 바꿈. 같은 날 여러 번 저장해도 이름이 겹침. 슬라이더를 마우스 휠로 움직이려 했는데 안 됨 (수정 기록 41, 49, 43)
  * PC·휴대폰: 요소가 화면 가장자리에 붙어 답답함. 저장 그림 여백이 화면과 다름 (수정 기록 52, 53)
  * 힐링 화면: 제목이 나무 감상을 방해함. 나무를 눌러 봤는데 아무 반응이 없음 (수정 기록 44, 45)
* 받은 피드백:

  * 휴대폰에서도 말풍선 안내를 볼 수 있어야 하고, 버튼이 겹치거나 잘리면 안 됨
  * 휴대폰은 손가락으로 대충 밀거나 눌러도 잘 움직여야 함
  * 저장은 팝업 없이 바로 되고, 파일 이름이 겹치지 않고, 기기 화면 비율(PC 16:9, 휴대폰 9:16)에 맞아야 함
  * 힐링 화면에서는 글자 없이 나무만 보고, 나무와 놀 수 있으면 좋겠음
* 반영 내용과 결과:

  * 휴대폰은 탭 한 번에 말풍선, 한 번 더 탭하면 실행 (수정 기록 37) → 중요한 안내를 보고 실행하게 됨
  * 휴대폰 세로 화면에서 슬라이더 창을 늘리고 제목을 나무 바로 위로 내림 (수정 기록 38, 39) → 겹침 없음
  * 일수 선택기 감도·관성, 슬라이더 휠·넓은 터치 범위 (수정 기록 40, 43, 47) → 휴대폰에서 대충 밀고 눌러도 잘 고를 수 있음
  * 이미지 저장: 휴대폰 저장, 팝업 없이 바로 내려받기, 파일 이름에 '_나무/_설명포함'과 시·분, PC 16:9·휴대폰 9:16, 화면과 같은 여백 (수정 기록 41, 48~51, 53) → PC·휴대폰 모두 겹치지 않는 이름으로 바로 저장됨
  * 사방 글자 5자 여백 (수정 기록 52), 힐링 중 제목 숨김 (수정 기록 44)
  * **이스터에그 (사용자 피드백으로 추가):** 나무를 누르면 잎이 후드득 떨어지고 5초 뒤 다시 돋아남 (수정 기록 45). 잎을 떨어뜨리고 5초가 지나면 잎 속에 숨어 있던 다람쥐가 줄기를 타고 내려와 잔디 위를 콩콩 뛰어가다 사라짐 (수정 기록 46). 안내에 없는 숨은 재미이며 계산 결과에는 영향 없음
  * 결과: 휴대폰과 PC에서 다시 한 바퀴 사용했을 때 겹침·잘림·저장 문제 없이 끝까지 진행됨. 모두 단풍나무_A_v3_Claude.html과 기획서_v3_기본.md·기획서_v3_상세.md에 반영됨 (완료 기준·추가 기능 포함, 수정 기록 54)
