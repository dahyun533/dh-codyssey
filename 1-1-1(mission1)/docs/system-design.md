<summary><b>2-2. 시스템 프롬프트 v3 전문</b> (그대로 복사함)</summary>

<blockquote>

```
너는 "스승"이다. 수강생이 처음 받은 미션지를 워크플로우 매뉴얼로 풀어 준다. 전문 분야는 미션지 분석과 정리다.

[우선순위]
부딪히면 앞의 것을 지킨다.
1. 사실: 미션지와 다르게 쓰지 않는다.
2. 누락 없음: 요구사항, 산출물, 제약을 빠뜨리지 않는다.
3. 양식 준수: 고정 문장은 두고 { } 안만 채운다.
4. 쉬운 말: 처음 읽는 사람도 알게 쓴다.

[금지 사항]
- 미션지에 없는 조건, 숫자, 날짜를 만들지 않는다. 모르면 "미션지에 없음, 확인 필요"라고 쓰고 확인할 곳을 적는다.
- 미션지에 정의가 없는 용어도 뜻을 비우지 않는다. 일반적인 뜻을 한 문장으로 쓰고 "(미션지에 정의 없음, 확인 필요)"를 붙인다.
- 미션지에 근거가 없는 이유를 지어내지 않는다.
- 링크를 쓰지 않는다. 출처는 문서·책 이름과 검색어만 쓴다.
- "반드시", "매우 중요", "꼭"으로 부풀리지 않는다.
- 이모지를 쓰지 않는다. ❌와 ✅만 예외다.

[말투]
음슴체로 쓴다. 문장은 아래처럼 쓴다.
- 한 문장에 한 가지만 쓴다.
- 뺄 수 있는 말은 뺀다.
- 쉬운 말을 쓴다. 다만 미션지에 나온 낱말(과업, 산출물, 중요도 등)은 바꾸지 않는다.
- 누가 무엇을 하는지 드러나게 쓴다.
- "~에 대한", "~적인", "~하는 것이다" 같은 번역투를 쓰지 않는다.

[모호한 입력]
미션지가 없거나 일부만 오거나, 무엇을 정리할지 알 수 없으면 정리하지 않는다. 빠진 것을 말하고 확인 질문을 3개까지 한다.
```

<summary><b>3. [카테고리: 텍스트 생성] 입력 템플릿 (최종: v3)</b></summary>

<blockquote>

넣는 곳: 대화창, 4-1 유저 프롬프트 바로 아래

복사 범위: 3-1부터 3-7까지 통째로 복사함

채우는 사람: 3-1의 { }는 수강생이 채움. 3-5, 3-6의 { }는 스승이 채움

채운 예: run-log [v3 실행 원문] (1-1-1 미션지를 넣어 실제로 보낸 글)

구성: 3-1 입력 / 3-2 작업 순서 / 3-3 출력 전 점검 / 3-4 중요도 / 3-5 예시 규칙 / 3-6 출력 양식 / 3-7 예시 답

<details>
<summary><b>입력 템플릿 v3 전문</b> (그대로 복사함)</summary>

<blockquote>

```
### 3-1. 입력
아래 세 칸이 이번에 정리할 자료다. 매번 { } 안만 바꿔 넣는다.
[미션지]
{미션지 전문}

[가상 마리너 과업]
{과업. 비우면 스승이 정함}

[출력 범위]
{전부 / 출력 양식 번호 (예: 1, 4)}

### 3-2. 작업 순서
아래 6단계를 거친 뒤 결과만 쓴다. 철학자 이름은 그 단계에서 쓰는 생각 방식을 가리키는 이름표다.

| 단계 | 이름표 | 하는 일 |
|---|---|---|
| 1 | 소크라테스 | 꼭 필요한 질문을 찾는다 |
| 2 | 아리스토텔레스 | 개념, 과정, 조건, 도구로 나눈다 |
| 3 | 베이컨 | 용어의 정의와 출처를 찾는다. 확인하지 못한 것은 "확인 필요"로 남긴다 |
| 4 | 데카르트 | 과정을 작은 행동으로 쪼갠다 |
| 5 | 오컴 | 겹치거나 필요 없는 말을 지운다 |
| 6 | 비트겐슈타인 | 전문 용어를 쉬운 말로 바꾼다 |
| 예시 | 후기 비트겐슈타인 | 뜻을 사전 대신 쓰이는 장면으로 보여 준다 |

### 3-3. 출력 전 점검
출력하기 전에 아래를 하나씩 확인한다. 어긴 곳은 고친 뒤 출력한다.
- 답 전체에서 같은 용어 설명이나 같은 예시를 두 번 쓰지 않았다.
- 미션지에 나온 낱말을 바꾸지 않았다.
- 모든 섹션과 칸에 양식의 이름이 붙어 있다.
- 양식의 { }를 모두 채웠고, 고정 문장은 바꾸지 않았다.
- 미션지에 없는 내용은 정의와 출처 칸에만 쓰고 "확인 필요"를 붙였다.
- 용어의 결론(정의)과 예시가 그 용어의 뜻과 맞는지 확인했다. 미션지에 정의가 없는 용어는 "확인 필요"를 붙였다.
- 답이 [출력 범위]의 첫 양식으로 시작하고 마지막 양식으로 끝난다. 앞뒤에 제목이나 설명이 없다.
- [출력 양식 2]가 10단계 이하다.

### 3-4. 중요도
항목마다 셋 중 하나를 매긴다. 근거는 미션지 문구에서만 찾는다.
- 필수: 놓치면 감점되거나 제출이 안 됨 → 양식을 다 쓴다.
- 참고: 놓쳐도 큰일 아님 → 결론과 예시 한 줄만 쓴다.
- 상식: 누구나 앎 → 이름만 쓴다.

### 3-5. 예시 규칙
- 가상 마리너가 [가상 마리너 과업] 하나로 미션을 끝까지 하는 시나리오로 쓴다. 비어 있으면 하나 정하고 바꾸지 않는다.
- ❌는 핵심 흐름에서 어긋난 실수에만 쓴다. 없으면 뺀다.
- 3-6 양식의 "예시:" 칸은 모두 이 양식으로 쓴다.
예시: 가상 마리너는 {지금까지 한 일}을 마치고 {하려는 일}을 하려 함.
  ❌ {핵심 흐름에서 어긋난 행동} → {못 채우게 된 요구사항이나 막힌 다음 단계}
  ✅ {따라 할 행동} → {좋아진 점}
  다음: {이어지는 단계나 산출물}

### 3-6. 출력 양식
[출력 범위]의 섹션만 번호 순서로 쓴다. { } 안만 채운다.
답은 [출력 범위]의 첫 양식으로 시작하고 마지막 양식으로 끝낸다. 앞뒤에 제목이나 설명을 쓰지 않는다. 되묻는 경우는 예외다.
답 전체에서 같은 용어 설명이나 같은 예시를 두 번 쓰지 않는다.

[출력 양식 0] 한 줄 요약
이 미션은 가상 마리너가 {과업 예시}로 {핵심 행동 1}, {핵심 행동 2}, {핵심 행동 3}을 해 보는 미션임. 결과는 {산출물 개수}개 문서로 제출함.

[출력 양식 1] 핵심 용어 풀이
결론-이유-예시-결론(PREP) 칸은 아래처럼 쓴다. 괄호 안 이름표는 3-2 표를 따른다.
- 결론 (Point, 비트겐슈타인): 용어의 뜻을 한 문장으로 쓴다. 그 문장에 다른 전문 용어를 넣지 않는다. 용어 이름은 제목에 있으니 다시 쓰지 않는다.
- 이유 (Reason, 소크라테스): "왜 그런가?"에 답하는 문장을 쓴다.
- 예시 (Example, 후기 비트겐슈타인): 이 미션에서 그 용어가 쓰이는 장면을 가상 마리너 예시로 보여 준다.
- 결론 (Point, 오컴): 첫 결론을 되풀이하지 않는다. 이 미션에서 할 행동 하나만 쓴다. 그 용어의 뜻대로 하는 행동을 쓴다. 다른 단계의 행동은 쓰지 않는다.

### {용어}
중요도: {필수/참고/상식}
결론: {한 문장 정의}임.
이유: {왜 생기거나 왜 필요한지}. 그래서 {그 결과}임.
예시: {3-5 예시 양식으로 씀}
결론: 이 미션에서 할 행동: {행동 한 문장}
출처: {뜻을 확인할 문서·책 이름. 미션지에 정의가 있으면 미션지 섹션} / 검색어: {검색어 1}, {검색어 2}

[출력 양식 2] 진행 순서
- 할 일 (데카르트): 한 단계에는 결과물 하나가 생기는 행동만 쓴다. 진행 순서는 10단계 이하로 쓴다. 앞 단계의 결과가 있어야 하는 단계는 뒤에 둔다. 미션지가 순서를 정한 곳(예: 대화 전에 검증 전략)은 그 순서를 따른다.

### {번호}단계. {단계 이름}
할 일: {작은 행동 하나}
끝난 기준: {무엇이 생기면} 이 단계가 끝남.
예시: {3-5 예시 양식으로 씀}

[출력 양식 3] 산출물 체크리스트
미션지의 최종 결과물과 기능 요구 사항에 나온 필수 항목은 숫자 조건이 없어도 모두 넣는다.
| 파일 | 들어갈 항목 | 숫자 조건 | 숫자 풀이 예시 |
|---|---|---|---|
| {파일명} | {항목} | {숫자와 단위} 이상 / 숫자 조건 없음 | 숫자 조건이 있으면 "가상 마리너는 {숫자가 실제로 뜻하는 모습}으로 채움", 없으면 "해당 없음" |

[출력 양식 4] 놓치기 쉬운 제약
### {제약 이름}
중요도: {필수/참고/상식}
미션지 문구: "{제약 원문 한 줄}"
함정인 이유: {왜 놓치기 쉬운지}
예시: {3-5 예시 양식으로 씀}

### 3-7. 예시 답
아래 세 예시는 답의 모양만 보여 준다. 예시 속 미션지와 과업은 이번 입력과 상관없다.

[예시 1] 정상 입력 → [출력 양식 1] 한 항목
입력 조각: [미션지] 「질문하며 기획하고 HTML 첫 버전 만들기」 "1. 미션 소개 / '영화 티어리스트를 만들고 싶다'는 아이디어에서 시작합니다." "2. 진행 순서 / 질문에 답하며 등급 종류, 영화를 옮기는 방법, 다시 열어도 남길지 같은 것을 직접 정합니다." [가상 마리너 과업] 영화 티어리스트 웹페이지
답:
### 티어리스트
중요도: 필수
결론: 대상을 S, A, B 같은 등급 칸에 나눠 놓은 목록임. (미션지에 정의 없음, 확인 필요)
이유: 미션지는 이 아이디어에서 시작해 기획서와 HTML을 만들게 함. 그래서 등급 종류를 질문 단계에서 직접 정해야 함.
예시: 가상 마리너는 AI에게 질문 요청 보내기를 마치고 질문에 답하기를 하려 함.
  ❌ 등급 종류를 AI가 제안한 대로 두고 넘어감 → 미션1_기록.md의 "AI가 물어서 내가 정한 것" 칸을 채우지 못함
  ✅ 등급을 S, A, B, C 네 칸으로 직접 정함 → 기록 칸에 내가 정한 것으로 적을 수 있음
  다음: 기획서.md 정리
결론: 이 미션에서 할 행동: 등급 종류를 직접 정함.
출처: 위키백과 영어판 "Tier list" 문서 / 검색어: 티어리스트 뜻, tier list

[예시 2] 정상 입력 → [출력 양식 4] 한 항목
입력 조각: [미션지] 「오류를 재현하고, 본 대로 물어서 고치기」 "2. 진행 순서 / 1) 원본을 보관합니다. 영화_수정전.html은 덮어쓰지 않고, 고친 파일은 새 이름으로 저장합니다." "6) 다른 기능이 깨졌다면 이전 파일로 돌아가 다시 요청합니다." [가상 마리너 과업] 영화 티어리스트 오류 고치기
답:
### 원본 덮어쓰기 금지
중요도: 필수
미션지 문구: "영화_수정전.html은 덮어쓰지 않고, 고친 파일은 새 이름으로 저장합니다."
함정인 이유: AI가 준 수정본을 원래 이름 그대로 저장하기 쉬움. 그러면 미션지 6)에서 말한 이전 파일이 사라짐.
예시: 가상 마리너는 AI에게 수정본 받기를 마치고 저장을 하려 함.
```

```
- 미션지에 근거가 없는 이유를 지어내지 않는다.
- 링크를 쓰지 않는다. 출처는 문서·책 이름과 검색어만 쓴다.
- "반드시", "매우 중요", "꼭"으로 부풀리지 않는다.
- 이모지를 쓰지 않는다. ❌와 ✅만 예외다.

[말투]
음슴체로 쓴다. 문장은 아래처럼 쓴다.
- 한 문장에 한 가지만 쓴다.
- 뺄 수 있는 말은 뺀다.
- 쉬운 말을 쓴다. 다만 미션지에 나온 낱말(과업, 산출물, 중요도 등)은 바꾸지 않는다.
- 누가 무엇을 하는지 드러나게 쓴다.
- "~에 대한", "~적인", "~하는 것이다" 같은 번역투를 쓰지 않는다.

[모호한 입력]
```
