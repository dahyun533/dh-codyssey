# 코랩 세션 리포트 · AI 기반 UI/UX 디자인 시안 제작

**미션:** AI에 입력할 지시문(프롬프트)으로 화면을 만들고, 글자를 고친 뒤 화면을 연결한 시제품(프로토타입)을 완성한다.

## 1장. 개요

이번 코랩 세션은 조원들이 각자의 작업을 마무리한 뒤 만나 결과물과 작업 과정을 공유하고 질문하며 비교하는 시간이었다. 팀원은 나를 포함해 총 5명이며, 이 중 1명은 현장에 오지 못해 Discord로 참여했다.

나는 게임 플랫폼 'PlayHub'의 기획서 작성부터 이미지 생성, 이미지 후가공, 작업 기록, Figma 화면 연결까지 결과물을 완성해 공유했다. 다른 조원들도 각자의 작업을 마무리한 뒤 결과물과 작업 과정을 공유했다. 노트북을 가져오지 않은 조원은 다른 팀원들의 작업을 살펴보고 질문하며 참여했다. 서로 Figma 사용법을 공유하고 작업 과정을 처음부터 끝까지 보여 주어, 팀원들이 이후 혼자서도 Figma를 사용할 수 있도록 했다.

### 4-3. 안전 점검

| 점검 항목 | 점검 결과 |
|---|---|

| 사용한 도구의 이용 약관과 만든 결과물의 사용 범위 | ChatGPT 이미지 생성을 사용했다. 도구의 현재 이용 약관과 적용 범위는 별도로 확인해야 한다. |
| 깨진 글자와 수정 필요 부분 | 세 장 모두 글자를 확대해 확인했고 깨진 글자는 없었다. 부자연스러운 요소 2건(아바타 화면 아이템 칸, 세 화면 상단 메뉴 위치 불일치)을 수정했다. |
| 조원과 비교한 작업 | 각자 작업을 마친 결과물을 공유하고 이미지 수정과 화면 연결 과정을 비교했다. 나는 글자를 프롬프트로 지정해 깨짐을 줄였고, 조원은 생성 이미지에서 사진을 잘라내고 한글·가격을 직접 다시 입력했다. |

## 5장. 조원 작업 비교

### 5-1. 작업 방식 비교

| | 비교한 작업 | 내 방법과 진행 상태 | 조원의 방법과 진행 상태 | 이후 작업에 미치는 영향 |
|:-:|---|---|---|---|
| 1 | 이미지에서 프로토타입까지 | 기획서, 화면 이미지, 후가공, 작업 기록, Figma 연결을 마쳤다. 코드 변환은 하지 않았다. | 조원들도 각자의 작업을 마친 뒤 결과물과 과정을 공유했다. 코드 변환까지 한 조원도 있었다. | 화면 배치와 연결 과정을 비교하며 각자의 작업을 이해할 수 있었다. |
| 2 | 이미지 속 글자 처리 | 영어 글자를 프롬프트에 따옴표로 정확히 적어 처음부터 깨지지 않게 했다. | 한글·가격처럼 작은 글자는 사진만 잘라내고 HTML/CSS로 다시 입력했다. | 한글이 많은 화면이라면 조원의 방법이 더 확실할 것 같다. |
| 3 | 작업 참여 방식 | 내 결과물과 작업 과정을 공유했다. | 노트북을 가져오지 않은 조원은 다른 팀원의 작업을 보며 질문했다. 한 명은 Discord로 참여했다. | 각자의 상황에 맞춰 결과물을 살펴보고 Figma 사용법을 공유할 수 있었다. |

### 5-2. 적용해 볼 점

| 공유 내용 | 인상적인 점 | 적용 방안 |
|---|---|---|
| 팀원 간 Figma 사용법 공유 | 작업 과정을 처음부터 끝까지 함께 보며 각자 사용할 수 있게 됐다. | 다음 작업에서도 도구 사용법과 화면 연결 과정을 공유한다. |
| 생성 이미지에서 사진만 잘라 쓰고 글자를 직접 입력하는 방식 | 작은 한글과 숫자도 읽기 쉽게 관리할 수 있었다. | 한글 화면을 만들 때는 글자를 이미지에 맡기지 않고 직접 입력하는 방식을 먼저 써 본다. |

| 항목 | 내용 |
|---|---|
| 예상 외 발견 | AI 없이 했다면 디자인 도구로 화면 3장을 직접 그리거나, 이미지 AI에 짧은 요청을 넣고 마음에 들 때까지 여러 번 다시 뽑았을 것이다. AI와 함께 하니 초안 결과에서 문제(메뉴·색·캐릭터 불일치, 기존 게임 요소)를 먼저 찾고 그 원인을 프롬프트 문장으로 바꿔 넣는 방식이 됐다. 그 결과 2단계 수정 한 번으로 글자 깨짐 없이 기획서에 가까운 화면이 나왔고, "정확히 적을수록 덜 다시 뽑는다"는 것을 알게 됐다. 처음 고른 Midjourney는 구독이 없어 ChatGPT로 바꿨다. |
| 반복 작업의 불편 사항 | AI 없이 했다면 Figma에서 화면마다 클릭 영역을 그리고 연결선을 하나씩 끌어야 했다(12개). AI와 함께 하니 연결할 곳만 정하면 배치와 연결이 한 번에 끝나서 반복 클릭은 줄었다. 대신 이미지 하나 생성에 1분 이상 걸렸고, 화면마다 같은 메뉴·색·마스코트 설명을 반복해서 적어야 하는 불편은 남았다. |
| 다음에 AI에게 더 맡기고 싶은 작업 | 기획서 한 장을 주면 AI가 ① 화면별 프롬프트 생성 → ② 여러 시안 생성 → ③ 글자 깨짐·색 규칙·메뉴 위치를 자동 검사(글자 인식·색 비교) → ④ 통과한 시안만 Figma에 배치·연결까지 하는 흐름을 맡기고 싶다. 공통 스타일(메뉴·색·마스코트)은 한 번만 정의해 모든 화면 요청에 자동으로 붙게 하면 반복 설명도 사라진다. 나는 "어떤 화면이 필요한가, 어느 시안이 기획 의도에 맞는가"라는 판단에만 집중하는 구조다. |

### 6-2. 수정 계획

| | 수정 사항 |
|:-:|---|
| 1 | 보너스 과제인 코드 변환을 해 본다. 완성된 화면 이미지를 HTML/CSS로 바꿔 Figma 시안과 비교한다. |
| 2 | 초안(v1) 이미지도 고해상도 원본으로 보관한다. 지금은 화면 캡처만 남아 있다. |

### 6-3. 유지 결정

| 유지 항목 | 유지 사유 |
|---|---|
| 홈 → 게임 목록 / 내 아바타 흐름과 상단 메뉴 이동 | 게임을 발견하고 고른 뒤 나를 꾸미는 이용 순서를 설명하기 쉽고, 어느 화면에서든 메뉴로 이동할 수 있다. |
| 원본과 후가공본을 따로 보관하는 방식 | 수정 전 버전이 남아 있어 무엇을 고쳤는지 확인하고 되돌릴 수 있다. |

### 6-4. 미해결 사항

| 미해결 항목 | 어려움을 겪었거나 확인할 부분 |
|---|---|
| 사용한 도구의 이용 약관 | ChatGPT 생성 이미지의 사용 범위를 아직 직접 확인하지 않았다. |
| 코드 변환(보너스) | 시간 안에 하지 못했다. |
